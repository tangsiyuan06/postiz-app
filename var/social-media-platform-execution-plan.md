### 3.2 Postiz 作为基础的具体差距

```
已有（可直接复用）：
  ✅ 28+ 平台 Provider 架构（SocialAbstract 基类）
  ✅ Temporal 工作流（定时任务 + 失败重试）
  ✅ MCP 端点（/api/mcp/{API_KEY}）
  ✅ NestJS 分层架构（Controller → Service → Repository）
  ✅ N8N/Zapier/Make.com 自动化集成
  ✅ AI 内容生成

需要新增（评论管理）：
  ❌ Provider 接口扩展：getComments() / replyComment() / hideComment()
  ❌ 各平台评论 API 对接（逐平台实现）
  ❌ 统一评论收件箱前端页面
  ❌ 评论 Webhook 注册与处理
  ❌ AI 评论审核层
  ❌ MCP 评论工具注册
```

### 3.3 开源方案的根本局限

1. **评论 API 平台政策限制**：Instagram / Facebook / TikTok 的评论 API 需要通过平台审核（App Review），普通开发者申请周期长（1-4 周），且有严格限制
2. **OAuth 维护成本**：28 个平台的 Token 刷新、权限范围变更需要持续维护
3. **AGPL-3.0 协议**：商业部署需要开源修改代码
4. **无现成评论管理**：从 0 开发需要一定的工作量（前端+后端+各平台 API 适配）

#### 4.4.1 各平台 UI 定性说明

**SocialAPI.ai**：有完整配套 Web App（`app.social-api.ai`），`/publishing` 内容发布 + `/inbox` 评论/DM/Reviews 管理均已有 UI 界面，同时具备 MCP（65 工具）+ REST API，支持人工操作与 Agent 自动化双模式。具体日历视图等细节需登录确认。

**Zernio**：有完整 Web App，内容日历、队列排期、批量发布、分析图表之外，`/dashboard/inbox-comments` 提供完整的评论管理 UI（支持 9 个平台评论 + IG/Telegram DM + FB/Google Reviews），还有隐藏/删除/点赞操作和实时通知。SOC 2 + GDPR 合规。Inbox 功能需单独付费 add-on。**MCP Server 提供 280+ 工具**（四者最多），支持发布、收件箱消息、评论自动化、联系人管理、广告管理、内容序列、分析等，支持托管（mcp.zernio.com）和本地两种部署方式，覆盖 14 个平台。

**Outstand**：纯 API 基础设施，无任何产品 UI，前端需完全自建。

**Ayrshare**：开发者向 Dashboard，可配置 Webhook、管理账号、查看调用历史，非终端用户产品 UI。

## 六、执行方案

### 6.1 方案一：基于 Postiz 二次开发

#### 核心思路
以 Postiz 开源代码为基础，补充评论管理模块，形成完整的内容发布 + 评论管理 + MCP Agent 一体化平台。

#### 可行性分析

**有利因素：**
- Postiz 已有完整的 Provider 抽象架构，只需为每个 Provider 实现 `getComments()`/`replyComment()` 接口
- 已有 NestJS 分层架构（Controller→Service→Repository），评论模块可复用同一模式
- 已有 MCP 端点，只需注册新的评论管理 MCP 工具
- 已有 Temporal 工作流，可复用实现评论 Webhook 监听和自动审核队列
- 当前代码库已有部分评论相关代码框架（git status 显示有 `comments/` 目录在开发中）

**不利因素：**
- 评论 API 需要逐平台申请权限（Instagram/TikTok App Review 审核耗时）
- AGPL-3.0 协议商业部署需购买商业授权（约 $500-1000/月，或与 Gitroomhq 协商）
- OAuth Token 维护工作量大（28 个平台，每个都有不同的权限范围）
- 评论管理前端需从零开发（按渠道视图 + 回复操作）

#### 优点

- ✅ **完全自托管**，数据完全自控，无平台锁定
- ✅ **成本最低**（除商业授权外，主要是开发成本）
- ✅ **平台覆盖最广**（28+ 平台，远超任何商业产品）
- ✅ **深度定制**，可任意扩展功能（AI 审核逻辑、工作流、UI）
- ✅ **MCP 原生集成**已有基础，评论 MCP 工具扩展成本低
- ✅ **技术栈熟悉**（当前项目即为此代码库，`comments/` 目录已在开发中）
- ✅ **无 API 速率限制**（直接对接平台 API）
- ✅ **大模型辅助开发**可大幅压缩实际交付周期，"长周期"风险显著降低

#### 问题与风险

- ❌ **评论 UI 需自建**：按渠道展示评论、回复操作等前端页面需要开发
- ❌ **平台 App Review 风险**：Instagram/TikTok 评论 API 审核可能被拒或延迟 4+ 周
- ❌ **AGPL 商业授权成本**：商业部署需与 Postiz 官方沟通授权费用
- ❌ **运维负担重**：28 平台 Token 刷新、API 变更需要持续跟进
- ❌ **缺少 AI 审核能力**：需要自行对接 LLM，无现成方案
- ❌ **X/Twitter API 成本高**：X API v2 评论相关接口付费门槛高（$100+/月）
- ❌ **视频发布平台配置不完整**：各平台视频规格（分辨率、码率、封面、字幕）配置依赖社区维护，预览与实际发布效果可能不一致，需自行补全各平台适配逻辑

- ❌ **Open API 需联系客服定制**，无法自助开通，不可程序化封装供 Agent 或客户调用
- ❌ **MCP 当前仅支持创建草稿**（Beta），评论操作通过 MCP 能力未经验证
